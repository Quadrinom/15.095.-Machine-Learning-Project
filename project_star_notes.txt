2. WAS THE RAW DATA CLEAN?
==========================================================================================

Structurally, yes:
  - every student_id is unique
  - all category values are valid (no typos or stray codes)
  - total_score = read + math everywhere it is defined
  - no student has a score in a year when they were not in STAR

There are 15 rows that look like duplicates (identical apart from student_id). These are
different students who each have only one year of sparse data and no test scores. They
aren't real duplicates, and they drop out of the analysis anyway because they have no
outcome.

The real problems are about study design rather than data errors: which treatment, which
outcome, which features, and how to handle missing values and randomization. Those are
covered in the next section.

4. MISSING DATA AND HOW IT WAS RESOLVED
==========================================================================================

Kindergarten cohort: 6,325 students
  - 539 missing the entry outcome (451 missing both scores, 85 missing reading only,
    3 missing math only). Dropped, because the outcome needs both scores.
    The missing share is the same in every class type (8.4-8.6%), so dropping these
    students should not bias the comparison between class types.
  - 34 in school 14 (no regular class). Dropped to keep every probability above zero.
  = 5,752 students in 78 schools
    (regular 2,005 / small 1,725 / aide 2,022)

Features in the analysis file
  gender          0 missing
  age at entry    4 missing  -> filled with the median, age_at_entry_missing = 1
  free lunch     17 missing  -> filled with the median, free_lunch_missing = 1
  ethnicity       1 missing  -> category "unknown"

Grade-3 outcome (outcome_g3): missing for 2,954 of 5,752 students (51%) because students
left the study. It is NOT filled in, and it should not be used as an outcome without
handling that loss (for example by weighting for attrition).

Age outliers: 10 students are more than 1.5 years from the typical age for their grade
(ages range from 3.8 to 7.5). They are flagged in age_outlier and kept.

6. OPT IMPLEMENTATION
==========================================================================================

IAI setup on this machine
  IAI 3.2.2 is installed for JULIA (juliaup channel 1.11.6/IAI/3.2.2, environment @iai,
  license at C:\Users\drkru\iai.lic). The Python wrapper (interpretableai) is NOT
  installed. Because the system image preloads IAI, Julia code calls it as `IAI.` and
  does not need a `using IAI` line. A single OptimalTreePolicyMaximizer fit needs a cp
  value; GridSearch tunes cp automatically.
  (The setup on Adi's Mac is different; see section 10d.)

Step 1 - Rewards (opt_rewards.py, Python/scikit-learn)
  python opt_rewards.py [--method dr|dm|ipw] [--model rf|linear] [--placebo]
  For each held-out school fold k:
    - Test rewards: fit one outcome model per class type (f_regular, f_small, f_aide) on
      all training schools, then compute equation (1) for the fold-k students.
    - Training rewards: cross-fitted inside the training schools, so a student's own
      fold never trained the model that scores them.
  p_t(x) comes from the p_* columns. The smallest is 0.16, so inverse-propensity weights
  stay at about 6 or less and no clipping is needed.
  Output: rewards_<method>_<model>.csv (test_fold, role, student_id, G_regular, G_small,
  G_aide). Default run on held-out data: regular -0.01, small +0.20, aide +0.00 SD.

Step 2 - Trees and evaluation (opt_trees.jl, Julia + IAI)
  julia +1.11.6/IAI/3.2.2 --project=@iai opt_trees.jl dr_rf
  For each fold k and each cost lambda in {0, .05, .1, .15, .2, .3}:
    - Subtract lambda from the small and aide training rewards (the budget penalty).
    - Fit GridSearch(OptimalTreePolicyMaximizer, max_depth 1-3, minbucket 50).
    - Predict on the fold-k schools and score with the test rewards (equation 4; no cost
      subtracted).
    - Compare with random allocation using the same shares, and with the free-lunch-first
      heuristic using the same number of small places.
  Also scores all-regular, all-small and all-aide.
  Output: results_<tag>.csv and fold-0 trees as HTML in trees_<tag>/.
  New since 2026-11-18 (--plant, evaluation tag, text trees for every fold): section 11.

Capacity constraints (equation 3)
  Standard OPT has no built-in way to cap counts per school. Options, easiest first:
    a) Cost penalty (implemented): sweep lambda. This controls the overall budget on
       average, but not school by school.
    b) Tree, then fill by school: use the tree's leaves as a priority order (by estimated
       gain G_small - G_regular). Within each school, fill B_s from
       project_star_school_capacity.csv in that order.
    c) Your own MIP: a depth-2 tree written as a mixed-integer program with constraint (3)
       added. Exact, but the most work.

7. WHAT TO EXPECT
==========================================================================================

- With no budget, the tree will probably be "everyone in small." Small classes help about
  +0.18-0.20 SD for nearly everyone, and aides add about 0. The interesting results only
  appear under constraints.
- Differences between students may be weak. A single student's DR reward is very noisy,
  so the tree can fit noise. Check whether real heterogeneity exists before tuning trees
  (placebo, semi-synthetic test, causal forest).
- With only about 6 features, depth 2-3 is plenty.
- A legitimate possible finding: targeting does not beat random allocation, because the
  benefit of small classes is about the same for everyone. Report it if that's what the
  data shows.

8. EXPERIMENTS
==========================================================================================

Core results
  1. Budget frontier (headline figure): plot policy value against the share of students
     in small classes (0-100%). Show OPT, random allocation at the same budget, and the
     free-lunch-first heuristic. OPT should sit above the other two.
  2. Per-school capacities: set B_s to 50% / 100% / 150% of the places each school
     actually had, using fill-by-school (option b above).
  3. Depth: compare depths 1-4, weighing the value each level adds against the
     interpretability it costs.

Methods comparison
  4. Reward estimators: the direct method vs IPW vs DR, each with linear and random-forest
     outcome models (--method / --model). Does the learned tree change?
  5. Propensities: the per-school p_* values vs the overall shares (about .35/.30/.35).

Equity and fairness
  6. Bottom-quartile objective: approximate it by giving extra weight to the rewards of
     students whose PREDICTED score in a regular class (f_regular) is in the bottom
     quartile. Vary the weight and report the trade-off between overall value and
     bottom-quartile value.
  7. Subgroup values: report every policy's value separately by free lunch, ethnicity and
     gender.
  8. Leaving out sensitive features: drop ethnicity and gender, then report the change in
     value and how many students' assignments change.

Making sure the results are real
  9. Placebo: shuffle class types within schools (--placebo) and rerun. OPT's gain over
     random allocation should go to about zero. If not, the pipeline is fitting noise.
 10. Semi-synthetic test: add a known effect to the outcome (for example, small classes
     help free-lunch students +0.3 SD more) and check that the tree finds that split.
 11. Stability: across the 5 folds and bootstrap resamples, how often do the same splits
     appear?
 12. Robustness: --cohort all; the grade-3 outcome (needs weighting for students who
     left); reading and math separately.

Requested by the teaching staff
 13. Subgroup-level allocation: give each combination of features its best class type
     (with a small linear program for capacities) and compare it with OPT on held-out
     schools. See section 10a.

Suggested order: 1, 9, 10 first. Together they show early whether there is real
heterogeneity for OPT to exploit.

9. FIRST RESULTS (DR rewards, random-forest outcome models, 5 held-out school folds)
==========================================================================================

Values are held-out policy values in SD units, averaged over the 5 folds
(results_dr_rf.csv). Each comparison uses the same share of small places as OPT.

  lambda  share small  OPT     random, same budget  free-lunch first
  0.00    0.92         0.160   0.162                0.176
  0.05    0.99         0.199   0.197                0.203
  0.10    0.86         0.140   0.154                0.163
  0.15    0.74         0.115   0.133                0.121
  0.20    0.67         0.125   0.117                0.123
  0.30    0.16         0.008   0.018                0.007
  Single-class-type policies: all small 0.199, all aide -0.002, all regular -0.016

What this shows
  - OPT does NOT beat random allocation or the free-lunch heuristic at any budget. Its
    gains range from -0.02 to +0.01 SD, while the spread across folds is 0.03-0.07 SD, so
    every difference is within noise. This fits the earlier finding that the small-class
    benefit is about the same for everyone in kindergarten.
  - The trees are shallow (chosen depth 1.2-1.8 on average). Even with no cost, fold 1
    sent 40% of students to aide classes, which is a sign of fitting noise.
  - The cost penalty does not control the budget smoothly: the share of small places
    jumps around between folds and is not monotone in lambda. For a clean budget
    frontier, fix the number of small places directly (for example, rank students by
    their leaf's estimated gain and fill a set share) instead of sweeping lambda.
  - The fold-0 trees are written out in section 10b.

Next steps this points to
  - Run the placebo (experiment 9) and the semi-synthetic test (experiment 10), to confirm
    the pipeline CAN find heterogeneity when it is there.
  - Try outcomes where heterogeneity is more plausible: the grade-3 outcome (Krueger finds
    larger gains for disadvantaged students over time), reading vs math, and the all-
    entrants cohort.
  - Run with --model linear and --method dm, which give less noisy rewards (experiment 4).

10. UPDATES 2026-11-18 (Adi)
==========================================================================================

a) Teaching staff feedback on the proposal (word for word)

  "Very interesting idea! One thing to consider is that, if you only have a few discrete
  pre-treatment features, students will fall into a limited number of subgroups. You
  could compute the best class type for each subgroup directly by brute force, averaging
  the estimated rewards within the subgroup and picking the highest (capacity limits
  could be added as a small linear optimization problem). Given that a shallow tree won't
  separate every subgroup, comparing your tree against this subgroup-level allocation on
  held-out schools would show whether the tree gives up any achievement for more
  interpretability and less risk of overfitting."

  What this means in practice (experiment 13)
    - Put every student in a group by their combination of features: gender x free lunch
      x ethnicity x locale (2 x 2 x 4 x 4 = 64 combinations), with age_at_entry cut into
      a few bands. Age is continuous, so it can't be used as is; the bands are still to
      be chosen.
    - In the training schools, average G_regular, G_small and G_aide within each group
      and give the group the class type with the highest average.
    - With capacities: decide how many students of each group get small / aide places
      with a small linear program over groups instead of over students.
    - Score it on the held-out schools exactly like OPT (equation 4).

  On the training data the subgroup policy can never score below a tree built on the
  same discrete features, because every tree leaf is a merge of groups. The real test is
  on held-out schools. Age is the exception: the tree picks its own age cut-off.

  How to read the comparison
    subgroup ~ OPT, both beat random   the tree keeps the benefit of targeting in a
                                       simpler form
    subgroup > OPT > random            targeting helps; the tree gives some of it up
    OPT > subgroup                     the 64-group table overfits small groups
    subgroup ~ OPT ~ random            no useful targeting on these features

  Caveats: "~" needs an uncertainty interval on the difference, not just similar point
  estimates (fold spread is 0.03-0.07 SD). Under capacities both policies must use the
  same seat-filling rule. Small groups will have noisy averages.

b) What the fold-0 trees say (trees_dr_rf/, trained on folds 1-4, 4,700 students)

  lambda  tree
  0.00    no split: everyone small
  0.05    age_at_entry >= 6.165 (130 students) -> regular; everyone else small
  0.10    suburban schools (1,051 students) -> regular; everyone else small
  0.15    same policy as 0.10
  0.20    girls (2,306) -> regular; boys (2,394) -> small
  0.30    no split: everyone regular

  The split changes feature at every lambda and no fold-0 tree uses free lunch, so these
  look like noise rather than real differences between students. No fold-0 tree assigns
  aide classes. The gender split needs care before it appears in a report. (Across all
  five folds, free lunch does appear at lambda 0.3, in 2 of 5 folds; see section 11d.)

c) Fixed-share frontier: method (opt_frontier.jl)
  For each held-out fold:
    1. Fit one OPT on training rewards for regular vs small only (GridSearch max_depth
       1-3, minbucket 50). Aide is left out: its estimated effect is about 0, and the
       frontier is about small seats.
    2. Lower the small reward by the MEAN training gain (G_small - G_regular). With no
       cost the tree usually doesn't split; with this cost every split has to separate
       students who gain more than average from those who gain less.
    3. Leaf gain = mean training gain in the leaf.
    4. For each share q = 0, 0.1, ..., 1 and each held-out SCHOOL s, give small places
       to round(q * n_s) students, highest leaf gain first (random tie-break); everyone
       else is regular.
  Random and free-lunch-first get exactly the same seat count in every school, which
  fixes the "matched over the whole fold, not per school" gap in 10c. Random is scored
  by its exact expected value. This is option (b) of section 6 with capacity
  B_s = q * n_s.
  Intervals (frontier_summary.py) resample whole schools, 2000 times. They hold the
  trees fixed, so they cover evaluation noise but not variation from refitting trees.
  The placebo (e) covers the whole pipeline.

  Smoke test (SYNTHETIC, +0.3 SD planted for free-lunch students): the tree splits on
  free lunch in 5 of 5 folds, with leaf gains 0.20 vs 0.51 in fold 0 (the planted 0.3
  difference). OPT beats random at q = 0.2-0.4 with intervals excluding 0, and ties
  free-lunch-first, which is the ideal rule in that test. At q = 0 and q = 1 all three
  policies are identical, as they must be.

d) Task 10: per-school capacities (opt_capacity.jl) - method
  Capacities (ASSUMED scenarios, not real budgets): B_s^small = round(c x observed small
  seats), B_s^aide = min(round(c x observed aide seats), n_s - B_s^small), from
  project_star_school_capacity.csv, for c = 0.5, 0.75, 1.0, 1.25, 1.5. The observed
  counts are for the same students (asserted n_total = n_s), so at c = 1.0 every school
  keeps the classes it actually had and only who sits in them changes. Average shares:
  c = 0.5: 15% small / 17% aide; 1.0: 30% / 35%; 1.5: 45% / 49%.
  Tree: one three-arm OPT per fold (GridSearch depth 1-3, minbucket 50). Small and aide
  training rewards are each lowered by their mean training gain over regular (as in the
  frontier). Leaf gains: mean training (G_small - G_regular) and (G_aide - G_regular).
  Seat-filling rule, identical for every policy in every held-out school:
    small seats first, to the B_s^small students with the highest priority; then aide
    seats, to the B_s^aide remaining students with the highest priority; the rest are
    regular. All seats are used (STAR schools had these classes anyway).
    OPT: priority = leaf small gain (aide gain breaks ties), then leaf aide gain.
    Free-lunch-first: free-lunch students first for small, then for aide. (This closes
    the "heuristic never uses aide seats" gap of task 12 for this script.)
    Random: exact expected value.
  Feasibility: opt, random and free-lunch-first use exactly B_s^small and B_s^aide in
  every school (asserted). tree_raw = the tree's own prescriptions with no capacities.
  This is a heuristic version of equation 3 (option b), not the exact MIP (option c):
  small seats are filled before aide, and the tree is fit without the constraints.

==========================================================================================
15. EXACT CAPACITY-CONSTRAINED POLICY (task 19) (2026-11-27, Adi)
==========================================================================================

a) Method (opt_exact.jl; summary: exact_summary.py)
  Goal: equation 3 INSIDE the fit, solved to certified optimality, and compared with
  the IAI policy of opt_capacity.jl at the same capacity scales c = 0.5-1.5.
  Policy class: a tree of depth <= 2 (every leaf >= 50 training students, as IAI's
  minbucket) plus two leaf orders: small seats go to leaves in one order, then aide
  seats to the remaining students in another. Seats are filled in every school exactly
  as in opt_capacity.jl (small first, then aide, every seat used, B_s = c x observed
  STAR seats). Ties inside a leaf are scored by their exact expected value.
  Candidate splits: every split IAI can make on these features (31 with all features:
  female, free_lunch, 15 age cut-offs, 7 two-way splits of ethnicity_grp and 7 of
  locale; 23 without gender and ethnicity). The missing flags cannot make a leaf of 50.
  Exactness: for each held-out fold EVERY valid tree (7,088-9,016 per fold; 3,160-3,582
  without gender/ethnicity) and EVERY pair of leaf orders is scored on the training
  schools with their own capacities, and the best is kept. That is the certified
  optimum of the training objective (sum of training rewards subject to equation 3 in
  every training school) over this class. No MIP solver was needed: the class is small
  enough to enumerate (about 40 s per run, single-threaded).
  Checks (asserted): the refit IAI tree reproduces opt_capacity.jl's saved leaves for
  the real run and all 20 placebos; exact >= IAI on the training objective whenever the
  IAI tree has depth <= 2 (all five folds of the main run).
  Placebo: the same 20 DR-RF shuffles as 12e, same features, through opt_exact.jl
  (exact and IAI policies).

b) Results, all features (DR-RF; held-out DR value; CIs: school bootstrap, policies fixed)

  In-sample, gain over random per training student (mean over folds):
     c      0.5    0.75   1.0    1.25   1.5
     exact  0.040  0.052  0.054  0.052  0.044
     IAI    0.021  0.029  0.022  0.011  0.005
  IAI's heuristic leaves about half or more of the attainable training gain unused.

  Held-out:

     0.5   +0.007        [-0.015, +0.029]  -0.012     [-0.033, +0.008]  +0.018      [+0.005, +0.034]

  Held-out exact - random: -0.018, -0.022, -0.029 [-0.054, -0.005], -0.006, -0.015 at
  c = 0.5 ... 1.5; p (best scale) = 0.95. Exact - IAI covers 0 everywhere. The exact
  trees split on age and free lunch, which carry no real signal (11, 12d), so the
  certified optimum fits noise and does WORSE than random at c = 1.0.

d) Note on tie-breaking (affects how opt_capacity.jl results are read)
  capacity_dr_rf.csv scores OPT with one random tie-break draw inside each leaf. Scoring
  the same policy with the exact expected value changes OPT - random noticeably, e.g.
  at c = 1.0 from +0.006 to +0.022. Random allocation is identical in both (asserted).
  With the expected value IAI's bootstrap intervals exclude 0 at c = 0.5-1.0, but the
  placebo run through the same pipeline gives p = 0.095 at the best scale: the bootstrap
  holds the trees fixed and is too optimistic; the placebo is the right yardstick.
  Conclusion unchanged: under per-school capacities no policy clearly beats chance.

e) What this means
  - Optimization works: the exact method certifiably finds policies worth about 2-4x
    more than IAI's on the training schools.
  - That extra in-sample value does not survive on held-out schools: exact and IAI are
    statistically indistinguishable (every exact - IAI interval covers 0), and both are
    within the placebo range. Without gender and ethnicity the exact optimum is worse
    than random. More optimization means more overfitting to noisy DR rewards.
  - For the report: the bottleneck is the noise in the rewards and the weak signal in
    the features, not the optimizer. A certified optimum is a useful check (it shows
    IAI is not leaving held-out value on the table), not a better policy.
